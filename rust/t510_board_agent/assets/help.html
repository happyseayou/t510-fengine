T510 Board Agent API

Stage 35 · v34 F-engine control baseline · OpenAPI 3.1 · Agent version 0.3.6

开发网络安全模式：security_mode=none。服务不校验 token、allowlist 或 mTLS，不启用 CORS。请仅放在受控实验室局域网中。

职责边界

Agent 只做配置和控制，并在请求时读取一次累计寄存器快照。它不抓取波形/频谱，不做 FFT、WebSocket 或 packet capture，也不计算 packet rate/drop rate（does not calculate packet rates）。独立的 Stage 34 reference watchdog 只轮询 LMK PLL1/PLL2 锁定状态并在物理参考失锁时执行安全 STOP；它不计算数据率或保存波形。Center Hub 应保存相邻 GET /api/v2/status 快照并计算速率。

每个硬件请求同步启动一次固定 Python helper。Agent 同一时刻只接受一个自身发起的硬件请求；冲突返回 409 HARDWARE_BUSY。Agent 不管理 Jupyter，也不能阻止 notebook 同时写硬件。

硬件接口

方法路径行为
GET/api/v2/status一次性读取 core、board ID、streaming、LMK profile/SYSREF、reference watchdog、ADC/DAC MTS target 与实测 latency、half-band coefficient ID、PPS/QSFP、数据通路健康和累计 counters。
GET/api/v2/rfdc/calibration读取八路 ADC 的 CalFreeze、OCB1/OCB2/GCB/TSCB 系数及固定顺序 SHA256。
GET/api/v2/rfdc/calibration/monitor从常驻reference watchdog读取每秒更新的freeze mask、四类系数、SHA256和温度，不启动一次性硬件helper。
GET/api/v2/telemetry/power-thermal?since_seq=N读取常驻watchdog有界JSONL环中的1秒AMS、stream、RFDC tile、校准哈希和OCB1 DFT记录；epoch变化或sequence缺口用于立即否决正式run。
GET/POST/api/v2/diagnostics/output-load读取或在停流时切换160 MS/s SPEC_ONLY/TIME_SPEC负载；不执行MTS、NCO、时钟或PFB配置，START要求匹配事务ID。
POST/api/v2/diagnostics/output-load/restore恢复负载事务之前的输出模式，并验证受保护配置指纹不变。
GET/api/v2/rfdc/power读取XRFdc_GetIPStatus规范化后的四个ADC/DAC tile状态及诊断事务。
POST/api/v2/rfdc/power/dac-shutdown停流时通过官方驱动关闭全部四个DAC tile并保持ADC tile运行；START要求匹配事务ID。
POST/api/v2/rfdc/power/restore执行完整production CONFIGURE/MTS恢复全部RFDC tile，不把简单StartUp作为正式恢复。
GET/api/v2/rfdc/calibration/ocb1读取OCB1动态/override状态、八路原始与signed16系数、DFT k=1..4、事务ID和SHA256。
POST/api/v2/rfdc/calibration/ocb1/snapshot-override停流且DAC静音时，将八路当前OCB1原值各自写回形成一次性override事务；要求receiver_stream_accepting=false。
POST/api/v2/rfdc/calibration/ocb1/release使用匹配事务ID解除八路OCB1 override；之后必须完整CONFIGURE/MTS。
POST/api/v2/rfdc/calibration/freeze停流且未 arm 时原子冻结八路；普通诊断要求 DAC 静音，受控训练事务校验声明的 center+60 MHz 八路单音，冻结后由同一 helper 静音。
POST/api/v2/rfdc/calibration/unfreeze停流、未 arm、DAC 静音时原子解除八路冻结。
POST/api/v2/rfdc/calibration/previewscience UDP 停止时抓取八路 RFDC preview，返回 RMS/peak dBFS 和 clip；用于训练电平门禁。
POST/api/v2/rfdc/calibration/train-freeze校验声明的八路 center+60 MHz训练单音；依据AMD PG269的−40 dBFS最低输入要求，使用带4 dB余量的−36..−8 dBFS工程窗口，以5 Hz等待GCB/TSCB连续2秒稳定，原子freeze后静音DAC。
GET/api/v2/clock/diagnostic读取Stage 34c-2时钟事务、完整LMK profile SHA、SYSREF request GPIO、预期物理输出、PLL锁定和MTS实测值。
POST/api/v2/clock/diagnostic/prepare仅在停流、receiver不接收、DAC静音、freeze=0且OCB1动态时，写入冻结profile、reset RFDC、执行MTS并返回一次性clock_transaction_id。
POST/api/v2/clock/diagnostic/restore恢复最后一次CONFIGURE明确选择的外部10 MHz或板载TCXO生产时钟，并重新reset RFDC和执行MTS。
POST/api/v2/configure加载 catalog bitstream，配置 profile/source/24 endpoints/board ID；完成后保持停流。重复调用会真实重配。
POST/api/v2/start校验 expected_board_id 后立即启动。
GET/api/v2/sync/status读取 scheduled-sync prepare/arm/commit、generation、sample0 和错误状态。
POST/api/v2/sync/prepare写入并冻结 generation、目标 PPS、TAI epoch、first_sample0、观测/信号链标签及 MTS 结果 ID。
POST/api/v2/sync/arm仅在所有板 prepare 成功后 arm；板端再次检查时钟、RFDC、PPS 和提前量。
POST/api/v2/sync/abort撤销 generation，并清空数据侧与 CMAC 侧流水。
POST/api/v2/stop无条件安全停止，双时钟域完整清空，并验证 counters 稳定和流水可恢复；无需请求体。
POST/api/v2/reset校验 expected_board_id，先安全停止并完整清空，再 reset。
PUT/api/v2/dac校验 board ID 与当前 RFDC DAC mixer 中心；中心不一致返回 409，绝不只改变 DDS 计算基准。随后短暂 mute，原子更新完整八路 DAC，phase commit，恢复 enable mask 并回读。

配置请求

endpoints 必须恰好 24 项，ID 0..23 各一次；0..7 为 TIME，8..23 为 SPEC。clock_reference 可显式选择 external_10mhz 或 onboard_tcxo；Stage 35 无 WR 观测使用后者，它在 MTS 后关闭 request-mode SYSREF，并以 free-run 相对采样时间工作，不需要外部 10 MHz 或 PPS。字段 sample_rate_msps 表示复采样率档位：160 是 160 MS/s，中心范围 80..1840 MHz；320 是 320 MS/s，中心范围 160..1760 MHz。160 支持三种 mode；320 明确拒绝 time_spec。ADC/DAC 模拟采样率为 3.84 GS/s，分别使用 12× 抽取/插值；UDP 数据格式保持不变。

curl -sS -X POST http://192.168.100.117:8010/api/v2/configure \
  -H 'Content-Type: application/json' \
  --data @config/t510/configure_160_time_only.example.json | jq

响应与错误

成功响应格式：{"request_id":"...","result":{...}}。错误格式包含稳定 code：

{
  "request_id": "t510-...",
  "code": "HARDWARE_BUSY",
  "message": "another Agent hardware request is running",
  "details": {}
}

常见 HTTP 状态：400 schema/JSON，404 unknown bitstream，409 busy/board-state conflict，503 Python/PYNQ/hardware unavailable，504 Python timeout。configure 默认 180 秒，其余硬件请求默认 10 秒。
